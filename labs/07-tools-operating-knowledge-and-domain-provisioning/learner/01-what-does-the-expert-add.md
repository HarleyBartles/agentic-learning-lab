# 01 — What does the expert add?

Lab 6 ended with a question:

> If a capable model already knows a lot about software engineering, what does a real software-engineering expert still add?

Today you are going to test that rather than answer it in theory.

No coding knowledge is required. You will not need to write code or understand source code.

## First, place yourself honestly

Tell the facilitator roughly how much software-engineering experience you already have.

You might be:

- completely new to software engineering;
- technically experienced in another area;
- a traditional software engineer who is new to agentic engineering;
- deeply experienced in some parts of software engineering and less experienced in others.

There is no preferred answer.

## Baseline

Ask the agent to propose or review the design and delivery approach for a small software application in plain English.

Do not ask for code.

Inspect the answer with the facilitator.

Notice what looks convincing at first glance.

Then listen for the kinds of questions an experienced engineer asks that may not have occurred to you:

- What important assumption is hidden here?
- What happens when something fails?
- Is this architecture solving the actual problem or showing off complexity?
- How would we know the system works?
- What has been left unspecified even though the answer looks complete?
- Which trade-offs matter here?

If you are already an experienced software engineer, add your own questions and challenge the facilitator where appropriate.

## Provision the worker

Choose a small number of recurring expert concerns from the discussion.

Instead of manually repeating them every time, work out how the agent could start future work with that knowledge already available.

Ask the agent to inspect the provisioned guidance, then run a comparable design or review task.

## Compare

Ask:

- What changed?
- Which changes came from better domain guidance rather than a different model?
- Did anything merely become longer rather than better?
- Which expert concerns are now visible earlier in the work?

Keep this question for the next phase:

> If expertise improves the worker, does an expert always have to be sitting in the room?

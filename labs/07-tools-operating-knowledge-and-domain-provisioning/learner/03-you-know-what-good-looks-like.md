# 03 — You know what good looks like

So far, the domain judgment came from either the facilitator or from shared partial understanding plus imported expertise.

Now choose something **you** know well enough to catch plausible mistakes that the facilitator might miss.

It does not need to be professional expertise.

It might be:

- a trade or profession;
- a hobby you have practised for years;
- a fandom with deep lore;
- a game or sport;
- a practical skill;
- a technical discipline;
- a subject people regularly ask you about.

The worked example is technical drawing. Another valid example might be Harry Potter lore if you know the canon well enough to catch chronology or source-boundary mistakes.

## Find the right domain

A useful test is:

> Could the facilitator hear a confident but subtly wrong answer and accept it, while you would spot the problem immediately?

If yes, the domain is probably useful.

## Baseline

Define one bounded task in that domain.

Ask the agent to attempt it with its current knowledge and capabilities.

Do not rescue it while it works.

Then judge the result yourself.

Ask:

- What did it already know?
- What looked plausible but was wrong?
- What specialist convention or edge case did it miss?
- Was the problem missing knowledge, missing capability, weak workflow, wrong assumptions, or weak verification?

The facilitator may ask questions, but you own the quality judgment here.

## Provision what is missing

Do not patch every mistake one sentence or detail at a time.

Identify the recurring expertise the worker should have before doing this kind of work again.

Decide where that knowledge belongs. It might be:

- reference material;
- project guidance;
- known-good examples;
- a reusable workflow or skill;
- tool guidance;
- quality criteria;
- verification rules.

Ask the agent to inspect the provisioned material and explain what it now thinks the important conventions, constraints, and quality criteria are.

Correct its understanding before it acts.

## Second pass

Give it a comparable task.

Then judge the result again.

Ask:

- What improved?
- What still looks wrong?
- Did we fix a knowledge problem or a capability problem?
- Did any provision add friction without helping?
- Would you trust this worker to do the next similar task with less supervision?

The important evidence is your judgment, not the agent saying it did better.

Keep one final question:

> Across all three phases, what exactly have we been building around the model?
